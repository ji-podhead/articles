The identity chain and the response ladder

A verdict is worthless if you don't know whom to freeze - commercial LLM firewalls return a judgment, and that's where it ends. None of them can pause the container that made the call, because none of them provisioned it.
IDENTITY - FLOWS DOWN FROM THE KERNEL-VISIBLE TRUTH
Host / VM
PID + socket → eBPF context. The kernel-visible truth about who is calling.
↓ Docker / CRI API
Container
container ID → Docker API. Which workload the PID belongs to.
↓ gateway lookup
Session
session ID, minted at provisioning - the agent presents it, never chooses it. Self-declared identity is fine for observability, worthless for enforcement. When network binding and token diverge, that divergence is itself a threat signal.
→
Graduated incident response - enforcement escalates as identity becomes certain
1revoke the session token
2inject a controlled error response
3SIGSTOP the container - memory intact for forensics
4blackhole its egress
