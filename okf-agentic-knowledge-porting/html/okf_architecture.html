OKF Architecture: Cheap Filter, Expensive Load

how an agent actually reads OKF - frontmatter first, bodies only when they earn the context window
YAML Frontmatter - the cheap part
okf_version: "0.2" - type: "Concept", the only mandatory field
topic, subtopic, tags, summary - the fields an agent lists and filters on
lifecycle: status + stale_after - an agent can refuse knowledge past its expiry date
generated by/at + sources - every claim traces back to its origin
a few hundred bytes per document, regardless of body length
→list, don't load
Markdown Body - the expensive load
one file, one concept - heading-bounded ## sections
cross-linked with normal Markdown links - links are the graph
loaded only for the filtered subset, one section at a time
no embeddings, no vector database, no reranker required
1. List, don't load - scan frontmatter only
2. Filter on structured fields, not prose - deterministic: topic == "general/container-runtime-security"
3. Load bodies only for the filtered subset - context tokens go to the survivors
4. Jump by headings - one ## section answers a follow-up, not the whole file
