Why two stages (the cost math)
RCF/ML over every event: ~$0, sub-ms, 24/7.
LLM triage: cents per call - spent only on
the ~0.1% of events the sorter flags.
An LLM on raw streams: too slow, too
expensive, too hallucination-prone.

Runtime sensor (Falco/eBPF)
the sensor side of the loop:
syscalls per container, container-attributed - the same events that feed Stage 1 make the kill precise.
(Falco doubles as the OSS Stage-1 runtime source in this architecture)
The guardrail that makes the automation safe
the agent gets a read-mostly tool catalog (query findings, read policies) - irreversible actions (kill a container, blackhole egress) stay policy-gated or two-step.
every automated action writes an audit event. An ML finding always carries confidence + model_version and ADDS to the rule layer - it never replaces it.
The LLM is the orchestrator, never the sensor.
