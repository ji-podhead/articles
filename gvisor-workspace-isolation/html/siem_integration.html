Three silent gates become one visible story

Figure 3 · Every isolation layer is also a log source; standard SIEM correlation, attributed to one workspace ID, turns three unremarkable events into one incident.
Identity Proxy (Layer C)
The access log is a ready-made audit trail: who reached what, and when they were denied.
→ gateway-style audit log
VLAN / ipvlan (Layer B)
A network IDS like Suricata watching each VLAN segment flags a packet that shouldn't exist at all - one tenant's traffic trying to cross into another's.
→ network-IDS finding, per tenant segment
gVisor sandbox (Layer A)
An eBPF runtime sensor like Falco watches the sandbox's syscalls directly (no sidecar needed) - a shell spawned where one shouldn't be, a known miner binary executing.
→ runtime-security finding
↓ all three attributed to the same workspace_id / owner
Correlation - the SIEM core
Same workspace/owner attribution across all three sources, within a few seconds of each other. No new infrastructure required - just a pipeline that treats these as first-class sources.
↓
One risk-ranked incident
"workspace X - a proxy denial, then a VLAN-102 IDS hit, then an anomalous syscall in the same sandbox, within seconds" - instead of three unremarkable-looking events nobody would have connected.
