MCP Servers via Docker + SSE Transport

A GenAI agent drives isolated email automation over Server-Sent Events
Google GenAI · agent layer
Interacts with the MCP server through the litellm module: simplified tool parsing, no manual tool handling, no Pydantic error fixing.
Fetches every tool the MCP exposes, automatically.

SSE Transport
Server-Sent Events as the remote access bridge: the agent talks to a running container, not to a local process.

Docker Container
Base image with the bridge preinstalled; a start script boots the stack. One isolated container per agent.
MCP-Bridge
Exposes the MCP remotely via SSE transport.
MCP Server (JS)
Email automation tools. Credentials live here in the container, never in the agent.
WHY THIS ARCHITECTURE
CI/CD friendly
Docker enables seamless continuous integration and deployment pipelines.
Secure isolation
Docker provides a secure and isolated deployment environment.
Network segmentation
Each agent gets its own container: restrict access and segment the network.
Automatic tool discovery
Install all MCP servers in the container, fetch all tools at once. No manual per-tool adds.
vs Claude Desktop
Similar solutions also run MCP in Docker, but locally; this stack deploys remotely over SSE transport.
Where it is heading
FastAPI dashboard with WebSockets, cronjobs that access the agent, webhooks and events that run workflows.
