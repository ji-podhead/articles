Layer 1, ingress identity: the gateway is the only place identity is ever decided

The client never gets a vote on its own identity: strip, resolve server-side, re-stamp, decide
An agent request arrives, carrying whatever identity claim it wants
Ten agents sharing one connector: compromised agent #7 signs as agent #3, and no log ever says which one did what.
↓
1
STRIP every client-supplied identity header, unconditionally
Before any other logic runs. A client-supplied copy of an identity claim is spoofing by definition, it never reaches a decision.
↓
2
RESOLVE the real identity server-side, from the credential that authenticated
Never from anything the request claims. The credential resolves to one row: a hashed, revocable key for a human, a workspace, or one specific spawned agent instance. Own row, independently revocable, independently attributable, never shared.
↓
3
RE-STAMP downstream identity headers from the verified row, only now
One ingress point re-stamps, everywhere else just trusts. No downstream code re-derives identity on its own.
↓
4
DECIDE with a deterministic policy engine, outside the model entirely
Allow, escalate to a human, or deny. Fail-closed on any error. RBAC becomes a hierarchy question: which role the agent got at spawn, what it is asking for now.
What the agent carries instead of a human's API key, four patterns, weakest to strongest isolation
1
Per-agent server-issued credentials
Minted at spawn, scoped at issuance (tools, budget, session), revoked per row.
2
OAuth token exchange, RFC 8693
Trade the incoming token for a narrower one: this action, this user, short TTL. The inbox agent never holds the user's Gmail grant.
3
Workload identity, SPIFFE SVIDs
Short-lived crypto identities attested from how the process launched. Stolen credentials expire in minutes.
4
Use-time injection
A sidecar holds the secret and injects it into the outbound call only. No credential file in the container to steal.
win: blast radius, a compromised agent stays trapped in its own session and role
win: attribution, logs say session, agent, user
win: tenant separation, the boundary check happens at the gateway
Multi-agent extension: one IAM role for the framework, per agent thread an AssumeRole call with a session policy scoped to that agent, 15-minute credentials injected into that process alone.
