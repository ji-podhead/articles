Layer 2, tool-call policy: four teams converged on the same shape

That convergence is a signal, not a coincidence: the decision is deterministic code, outside the model
Meta · LlamaFirewall (Purple Llama, arXiv 2505.03574)
PromptGuard 2 and CodeShield are content layers; Agent Alignment Checks audit the reasoning, they don't authorize. Kept separate on purpose.
CodeShield's engineering spec: Insecure Code Detector covers 7 languages and 50+ CWEs, and a two-stage scan keeps ~99% of requests under 70 ms, with only suspicious code paying a 450 ms p90 deep scan. That latency shape is what makes a scanning stage viable inside a gateway.
OpenAI · Operator, the ask layer in numbers
Proactive refusals: 97% recall on agentic harms, 94% on high-risk categories like banking. Model mistakes: a 13-per-100-task baseline (5 irreversible or severe) cut by ~90% through confirmations with 92% recall. Watch mode pauses execution on email sites when the user looks away.
The honest bill: the tightened ask layer overrefuses much more than GPT-4o, 55% vs 90% on their not-overrefuse metric. A safer ask layer costs convenience, OpenAI published the invoice.
Google · Vertex AI / Agent Development Kit
Tool calls are matched deterministically against a pre-defined OpenAPI schema: a call that doesn't exactly match is rejected by the API gateway itself, not by asking the model to reconsider. The schema check is code, not a second model call.
AWS · Bedrock AgentCore (2025)
AgentCore Identity brokers short-lived, per-agent STS credentials (AssumeRole plus a per-call session policy) instead of a standing IAM role; AgentCore Gateway sits in front of every tool call, evaluated against Cedar, AWS's own deterministic, formally verified policy language.
The pattern all four converge on
1
A short-lived, per-agent credential, never a standing role or a secret shared across every agent instance.
2
Identity resolved server-side, from the credential, never from what the request or the model's output claims.
3
The allow/deny decision is deterministic code: Rego, Cedar, an OpenAPI schema match, not a second model judging the first one's tool call.
4
Content-safety scanners are a separate, complementary layer, never a substitute for the authorization decision.
The most common conflation in this space: content-safety scanners answer "is this text or code dangerous." They don't answer "is this agent allowed to call this tool."
