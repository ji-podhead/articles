Taxonomy vs. ontology - the two halves of the blueprint of knowledge

A taxonomy routes: it decides in milliseconds what is irrelevant. An ontology reasons: it defines the concepts, properties and typed relations a domain is allowed to use.
Taxonomy - a classification schema
Objects sorted into categories by fixed criteria. Rigid by design: every document has exactly one home - and that rigidity is the superpower.
Incoming document or query
"Discharge letter, cardiology" or "CO2 spike, wing B"
↓ route: pick the one right branch, exclude everything else
Medical corpus
patients_data · medical_knowledge
Building corpus
building_documents · technical_manuals
Deciding what is irrelevant takes milliseconds and requires no model at all - no embedding, no LLM, no similarity computation.
Ontology - a formal, machine-readable rule set
Defines the concepts of a domain, their properties, and above all their typed relations to each other.
Examples of typed relations
medication TREATS diagnosis
diagnosis HAS_SYMPTOM finding
sensor HAS_POINT room
patient HAS_DIAGNOSIS code · lab value IS_INDICATOR_FOR diagnosis
The blueprint is usually already drawn
Mature industries maintain their ontologies: SNOMED CT and ICD-10 for diagnoses · LOINC for laboratory values · Brick Schema for buildings. RAG architecture is about wiring your data into it, not inventing one.
Job: validate every hop - precise traversal, no logically impossible conclusions.
Taxonomy routes · ontology reasons - both together are the blueprint
Use the taxonomy to exclude domains instantly; use the ontology to validate every hop the agent wants to take.
