GraphRAG - from triples to communities to answers

Rebuilding the topology a flat index loses: entities and edges become a graph, Leiden clusters summarize it, and two search modes answer what similarity never could.
Documents
unstructured text · manuals · charts
→
Entity + relation extraction
An LLM identifies nodes (entities like "Metformin" or "Patient Müller") and edges (relations like "treats" or "takes"), producing triples:
(Metformin) -[treats]-> (Diabetes)
→
Knowledge graph
nodes + typed edges - the pipeline finally knows what is related, not just what is similar
→
Leiden communities
Community detection groups related nodes into clusters, summarized at several abstraction levels
Local search
Navigates the edges around a specific node - multi-hop detail ("which devices are affected when pump X fails?"), validated against the ontology.
Global search
Reads the precomputed cluster summaries and answers corpus-level questions - "What are the most common side effects in this patient group?" - without scanning a single raw document.
Grounded, explainable answer
The retrieval path is the evidence trail.
Where the ontology meets the graph
Constraint-based extraction: the LLM is bound to the ontology classes (SNOMED, Brick) - a clean entity base, no cleanup project. Semantic enrichment: node "Room 101" acquires every property of class "office room". Path validation: the graph says what is connected; the ontology says what is allowed to be connected.
