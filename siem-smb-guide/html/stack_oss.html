The open-source stack: four sensors, one manager, one indexer

Every box is a real, separately maintained open-source project - nothing here is a single vendor's product.
SENSORS - ONE PER SIGNAL TYPE, PER HOST AND PER CONTAINER
Suricata - network IDS/IPS
signature rules on raw packets; the XDP/eBPF capture mode drops matches at the NIC. Blind spot: inside TLS, inside a process.
eBPF sensor - e.g. Falco
watches syscalls per container, no sidecar, no code change: shell spawns, namespace escapes, crypto-miners.
Host agent - e.g. Wazuh agent
file-integrity monitoring, vulnerability scanning, container-engine visibility.
Firewall logs - nftables / ufw
which ports were probed, from where, how often. The most underrated signal - if you turn drop logging on.
↓ ship every signal
SIEM core - e.g. the Wazuh manager: rules + correlation
Answers the question no sensor can answer alone: is this one incident or four unrelated events? Runs as a single-node docker-compose stack, roughly 4 GB of RAM.
↓ structured, timestamped alerts
Indexer + dashboard - OpenSearch
Full-text search over months of history, retention, and pre-built compliance views for PCI-DSS, GDPR and HIPAA.
What you get
compliance dashboards, a maintained detection ruleset, search over history - and every byte stays in infrastructure you control, the simplest answer to a data-residency question.
What it costs
roughly 4 GB RAM, the discipline of applying updates, and you now operate something Elasticsearch-adjacent.
