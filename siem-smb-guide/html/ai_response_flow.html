The two-stage AI security response: cheap detection, expensive thinking

A small, always-on statistical model does the initial sorting; the expensive LLM agent only wakes up when the sorter flags something - edge-to-core triage.
STAGE 1 · DETECT - ALWAYS-ON, STATISTICAL, ~FREE
Log streams
egress drops · bytes_sent · model invocations · syscalls - every event, 24/7, zero tokens.
→
Anomaly detector - the sorter
RCF / embeddings + KNN / SLM distills - statistical, not generative. Knows "pod B sends 400x its 14-day baseline"; has no idea what an SQL injection is. AWS: GuardDuty ML · OSS: OpenSearch ML Commons.
→
Archive - the normal path
The 99.9% of events that are business as usual go to long-term retention. Nothing is dropped.
↓ anomaly? - the only gate into Stage 2; LLM tokens are spent nowhere else
STAGE 2 · THINK + ACT - ONLY ON FLAGGED EVENTS
Orchestration fires
AWS: GuardDuty finding → EventBridge rule → Step Functions state machine. OSS: an alerting monitor watches the anomaly-results index.
→
Reasoning agent - the thinker
2026-class models (DeepSeek-R1 / Claude 5-gen) reason step by step before a verdict. RAG over runbooks + context tools: IP reputation, maintenance windows, identity history, FIM state. AWS: Bedrock Agent · OSS: agents-tools.
→
Verdict: real attack?
The agent correlates the numeric anomaly with everything the math alone could not understand.
Scoped response playbook - agent tool-calls
network kill: attacker IP → eBPF map
  → XDP_DROP at the NIC, before the TCP stack
syscall kill: BPF-LSM intercepts execve
  → EACCES or SIGKILL the PID
# the process dies, the container survives - forensics
False positive - documented, then fed back
Detector thresholds and baseline retrain absorb the lesson. The loop keeps the model alive when a legitimate traffic pattern changes.
Why two stages - the cost math
Statistical detection over every event: ~$0, sub-millisecond, 24/7. LLM triage: cents per call - spent only on the ~0.1% of events the sorter flags. An LLM watching raw streams would be too slow, too expensive, too hallucination-prone.
The guardrails that make the automation safe
Read-mostly tool catalog for the agent (query findings, read policies) · irreversible actions stay policy-gated with a human in the loop · every automated action writes an audit trail · every ML finding carries confidence + model_version and adds to the rule layer - it never replaces it. The LLM is the orchestrator, never the sensor.
